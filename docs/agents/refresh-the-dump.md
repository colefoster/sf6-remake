# Refreshing the dump from a live game

## The problem this exists to solve

`data/raw/mmdk/source.json` pins the pipeline to a **third-party snapshot** of
SF6's `CharacterAsset` data — `alphazolam/MMDK` at one commit, 24 characters.
FAT's frame data in `data/raw/SF6FrameData.json` is current and covers 30.

So every disagreement `sf6 verify` reports has two possible causes:

1. we read the dump wrong, or
2. the dump is **older than the frame data we grade it against**.

No ADR has ever separated these. Until the diff below is run, "93.2%" means
"93.2% modulo an unknown amount of version skew", and any decode built on the
residual is standing on sand. This is worth remembering before attributing a
few percent to a clever mechanic.

## The atemi table is a separate button

MMDK's character dump has no atemi table, which three ADRs were written around.
Its **Dump Atemis** button does: `common_atemi.json` at the dump root, plus
`<Char>/atemi.json` for the fighters with private rows (Luke, Marisa, Zangief).
Press it while you are in there — `extract-geometry.mjs` reads both layers if
they are present and falls back to ADR-0039's FAT-derived hit counts if they are
not.

An atemi **index is only meaningful with the table from its own build**. Between
the pinned snapshot and the Aug-2026 dump, Luke's Sokutou moved from row 6 to 5
and Zangief's 5HP from 6 to 7. Pasting one dump's table onto another's geometry
resolves armor onto the wrong row — silently, and in Zangief's case onto a row
that takes no damage at all. See
[ADR-0042](../adr/0042-the-atemi-table-was-behind-another-button.md).

## What is missing from the pinned snapshot

Geometry exists for 24 of FAT's 30. Absent: **Alex, C.Viper, Elena, Ingrid,
Mai, Sagat**. They are excluded from every geometry-based check and cannot be
played in the runtime. Terry and M.Bison are present, which dates the snapshot
to roughly mid-Year-2.

The Aug-2026 live dump in `data/raw/mmdk-fresh/` covers **21** — the same roster
minus **Ed, M.Bison and Terry**, which nobody has dumped by hand yet. So neither
tree contains the other, and re-pinning would trade three playable fighters for
a year of patches. Both stay.

## Getting a live dump

MMDK does not read files off disk. It is a REFramework Lua script that dumps
the deserialized `CharacterAsset` objects **out of the running game**, so a
human has to launch SF6 and drive its UI. There is no headless path.

Extracting from `re_chunk_000.pak` instead would avoid the game entirely, but
the assets in there are MurmurHash-named `.user.2` blobs, and MMDK's real value
is the object → JSON conversion that `extract-geometry.mjs` already assumes.
Rebuilding that is a project, not a shortcut.

The wizard automates everything either side of the human part:

```
bash refresh-dump.sh          # generated by the /wizard skill; ephemeral
```

It installs REFramework and MMDK on the Windows box over SSH, waits while you
dump one character in-game, pulls the JSON back into `data/raw/mmdk-fresh/`,
and runs the diff. Set `CHAR=Mai` to do a different fighter.

## The diff

```
MMDK_RAW=data/raw/mmdk-fresh GEOMETRY_OUT=/tmp/fresh \
  node scripts/extract-geometry.mjs Ryu
node scripts/diff-geometry.mjs data/geometry/ryu.json /tmp/fresh/ryu.json
```

`extract-geometry.mjs` honours `MMDK_RAW` and `GEOMETRY_OUT` precisely so a
second dump can be extracted beside the pinned one without disturbing it.

`diff-geometry.mjs` compares the **extracted artifact**, not the raw dump. Ryu's
`moves_dict` alone is 8.6 MB of mostly-cosmetic keys; the extracted file is the
subset the engine consumes, so anything the diff reports is something that can
change an answer. It looks at action lengths and `MarginFrame`, hit-key windows,
projectile launch speed, the outcome table's damage/stun/`DownTime`/`DmgType`/
`DmgRecover`, and which action each notation maps to.

## Reading the result

**No changes** — version skew is dead as an explanation for that character, and
every disagreement it has is ours. Say so in the next ADR; it retroactively
strengthens every percentage in the project.

**Changes** — note which fields moved before trusting any check that reads them.
A `move -> action` change is the loudest possible signal: it moves every check
for that move at once.

Either way the fresh tree stays in `data/raw/mmdk-fresh/` (gitignored) and
`data/geometry/` is untouched, so both readings remain side by side.

## Do not silently re-pin

Replacing the snapshot wholesale re-baselines every number in every ADR in one
commit, with no way to tell which moved because the game changed and which moved
because the reading changed. Diff first, one character at a time, and record
what moved.
